# Volna

Музыкальное приложение в духе Spotify: единый поиск по сервисам, персональная «Моя волна», плейлисты, загрузка своих файлов, встроенный прокси и кастомный плеер со скоростью Slowed / Normal / Speed.

Работает как настольное приложение на Electron с локальным сервером на `127.0.0.1:45871`.

## Что умеет

- **Поиск по сервисам**: Deezer, Apple Music, Bandcamp и Яндекс Музыка работают сразу, без входа. Вход в Deezer и Яндекс Музыку — опциональный: на поиск он не влияет. Spotify, YouTube Music и VK подключаются входом в аккаунт сервиса — без ручного ввода Client ID и Secret.
- **Bandcamp без регистрации**: полные треки из открытых страниц артистов. Если сайт недоступен в сети — свой HTTP/HTTPS/SOCKS5-прокси или готовый конфиг для zapret (вкладка «Настройки → Прокси»).
- **Яндекс Музыка при блокировке по IP**: если API отвечает captcha `HTTP 403`, включите отдельный прокси в «Настройки → Прокси». Поиск остаётся без входа; полные треки требуют аккаунт.
- **«Моя волна»** — 5 режимов (Обычная, Энергия, Спокойная, Ночь, Открытия), подстраивается под лайки и историю.
- **Аккаунты** — регистрация и вход по логину/паролю или через Google OAuth. Пароли хранятся как scrypt-хеши.
- **Плейлисты** — создание, переименование, добавление/удаление треков, сортировка, обложки-мозаики.
- **Любимые треки и история** прослушиваний.
- **Свои файлы** — mp3, flac, wav, m4a, ogg, aac до 200 МБ; drag & drop в окно.
- **Плеер** — очередь, перемешивание, повтор, перемотка, громкость, Slowed / Normal / Speed с настройкой тона, bass boost, Media Session.
- **Встроенный прокси** — обходит CORS и hotlink-ограничения, поддерживает Range (перемотку), кэширует обложки и ответы поиска.
- **Оформление** — тёмный стеклянный интерфейс, 6 акцентных тем, выбор шрифта, свой фон, настройка размытия и прозрачности, режим уменьшенной анимации.

## Запуск из исходников

Нужен Node.js 20+.

```powershell
cd D:\Volna
npm install
npm run dev
```

Откройте `http://127.0.0.1:45871` — это тот же интерфейс, что и в приложении.

Запуск в Electron:

```powershell
npm start
```

## Сборка

```powershell
npm run icon     # перегенерировать build/icon.ico и build/icon.png
npm run build    # NSIS-установщик + portable
```

Готовые файлы появятся в `dist`:

- `Volna-Setup-1.0.0.exe` — установщик (ярлыки на рабочем столе и в меню «Пуск», выбор папки).
- `Volna-Portable-1.0.0.exe` — портативная версия без установки.

Отдельные цели: `npm run build:setup`, `npm run build:portable`.

> Если сборка падает на распаковке `winCodeSign` с ошибкой создания символических ссылок (нет прав администратора), распакуйте кэш вручную без папки `darwin`:
>
> ```powershell
> $c = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
> & .\node_modules\7zip-bin\win\x64\7za.exe x "$c\*.7z" "-o$c\winCodeSign-2.6.0" "-xr!darwin" -y
> ```
>
> После этого повторите `npm run build`.

## Где хранятся данные

- **Установленная версия**: `%APPDATA%\Volna\data\volna.json` и `%APPDATA%\Volna\data\uploads`.
- **Режим разработки**: `D:\Volna\data`.

В `volna.json` лежат пользователи, сессии, плейлисты, лайки, история и настройки. Удалите папку `data`, чтобы сбросить приложение.

## Настройка Google OAuth

1. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создайте OAuth Client ID типа **Web application**.
2. Добавьте точный redirect URI:
   ```
   http://127.0.0.1:45871/api/auth/google/callback
   ```
3. Пропишите Client ID и Client Secret в `config.json` (или задайте переменные окружения `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`).

Вход открывается в системном браузере, приложение опрашивает статус и автоматически входит после подтверждения.

> **Важно:** секрет Google OAuth из этой сборки уже был показан в переписке. Считайте его скомпрометированным: создайте новый Client Secret в Google Cloud Console и обновите `config.json`. Не передавайте `config.json` третьим лицам.

## Вход в музыкальные аккаунты

Настройки → Интеграции. Пользователь нажимает **«Войти в аккаунт»**, подтверждает доступ на официальной странице сервиса в браузере, и Volna сама получает токен. Никаких полей `client_id` и `secret_key` в интерфейсе нет: пароли вводятся только на сайте сервиса и в приложение не попадают.

| Сервис | Что видит пользователь | Воспроизведение |
| --- | --- | --- |
| Deezer | «без входа»; вход — на всякий случай | 30-секундные превью |
| Apple Music | «без входа» | 30-секундные превью |
| Bandcamp | «без входа» | полные треки (до 50 результатов на запрос) |
| Яндекс Музыка | «без входа» (вход — для полных треков) | 30-секундные превью / полные треки с аккаунтом |
| Spotify | вход в аккаунт | поиск (превью, если отдаёт API) |
| YouTube Music | вход через Google | только поиск |
| VK Музыка | вход в аккаунт VK | только поиск (зависит от прав API) |
| Локальные файлы | — | полное воспроизведение |

### Что нужно настроить один раз (для сборки приложения)

Приложение должно быть зарегистрировано у каждого сервиса — это делает автор сборки, а не пользователь. Данные приложений хранятся в `config.json` в блоке `oauth` (не показываются в интерфейсе) или задаются переменными окружения `DEEZER_CLIENT_ID`, `DEEZER_CLIENT_SECRET`, `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `VK_CLIENT_ID`, `VK_CLIENT_SECRET`.

Redirect URI для каждого сервиса:

| Сервис | Redirect URI |
| --- | --- |
| Deezer | `http://127.0.0.1:45871/api/integrations/deezer/callback` |
| Spotify | `http://127.0.0.1:45871/api/integrations/spotify/callback` |
| Яндекс Музыка | `http://127.0.0.1:45871/api/integrations/yandex/callback` |
| VK Музыка | `https://localhost:45872/api/integrations/vk/callback` (HTTPS обязателен) |
| YouTube Music | `http://127.0.0.1:45871/api/auth/google/callback` (тот же, что для входа в Volna) |

YouTube использует уже настроенный Google OAuth-клиент, поэтому вход в YouTube Music работает сразу после настройки Google. Для Spotify и Яндекс Музыки заполненные Client ID и Client Secret уже лежат в `config.json`, поэтому кнопка «Войти в аккаунт» сразу запускает полный OAuth.

VK требует HTTPS для Redirect URI. Volna поднимает локальный HTTPS-прокси на `https://localhost:45872` и пробрасывает callback на основной сервер. Сертификат лежит в `certs\localhost.pfx` и создан для `localhost`. Если браузер ругается на самоподписанный сертификат, установите его в «Доверенные корневые центры сертификации» текущего пользователя или подтвердите переход вручную. YouTube, Spotify и Яндекс используют обычный `http://127.0.0.1:45871`.

Токены доступа хранятся локально в базе пользователя (`userData`), обновляются автоматически по refresh-токену и удаляются кнопкой «Выйти».

Deezer, Apple Music и Яндекс Музыка без входа отдают официальные 30-секундные фрагменты. Bandcamp отдаёт полные треки из открытых страниц артистов — без регистрации и входа. Полные треки Яндекс Музыки доступны после входа в аккаунт. Приложение не обходит подписки и не скачивает закрытый контент.

### Bandcamp и Яндекс Музыка: если сервис недоступен

Настройки → Прокси. У каждого сервиса свой переключатель и своё поле адреса; если адрес для Яндекса оставить пустым, используется адрес из блока Bandcamp. Для Bandcamp есть два независимых способа:

1. **Свой прокси** — включите переключатель и укажите `http://…`, `https://…` или `socks5://…`. Через него идут поиск, страницы треков и аудиопоток Bandcamp. Адрес можно также задать в `config.json` → `network.bandcampProxyUrl`.
2. **zapret** — кнопка «Скачать конфиг» сохранит `volna-hostlist.txt`, `volna-zapret.bat` и инструкцию. Запустите BAT от имени администратора рядом с `zapret.exe`. Список содержит домены Bandcamp, Яндекс Музыки и остальных музыкальных сервисов.

Для Яндекс Музыки включите переключатель «Через свой прокси» в блоке «Яндекс Музыка: обход блокировки» и при необходимости задайте отдельный адрес в `config.json` → `network.yandexProxyUrl`. Через прокси идут поиск, получение ссылок на треки, аудио и обложки. Это лечит ошибку `Яндекс: блокировка по IP (403). Проверьте прокси в настройках`: прямое подключение к API Яндекса часто уходит на капчу с облачных IP и IP дата-центров. Вход в аккаунт для поиска не нужен и сам по себе 403 не убирает.

По умолчанию и Bandcamp, и Яндекс Музыка работают напрямую, без прокси; Bandcamp ещё и без входа.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Space` | пауза / продолжить |
| `←` / `→` | перемотка на 5 сек (`Shift` — 30 сек) |
| `↑` / `↓` | громкость |
| `L` | лайк |
| `M` | выключить звук |
| `Q` | очередь |
| `N` | полноэкранный плеер |
| `S` | Slowed → Normal → Speed |
| `Ctrl+K` | поиск |

## Структура

```
electron/     главный процесс, preload, окно и IPC
server/       Express: auth, музыка, прокси, библиотека, хранилище
public/       интерфейс без сборки (ES-модули, CSS)
scripts/      генератор иконок и UI smoke-тест
build/        иконки приложения
config.json   OAuth и интеграции
```

Проверка интерфейса в Electron (нужен запущенный `npm run dev`):

```powershell
.\node_modules\.bin\electron.cmd scripts\ui-smoke.js
```

## Ограничения

- Порт по умолчанию `45871`. Если его займёт другая программа, сервер попробует следующий, но Google OAuth привязан к `45871`.
- Яндекс и VK зависят от актуальности пользовательского токена и могут требовать повторной авторизации. Поиск Яндекса может блокироваться капчей по IP (403) — в этом случае поможет прокси из настроек; токен на поиск не влияет.
- Плейлисты, лайки и настройки синхронизируются только с локальным сервером — облака нет.
